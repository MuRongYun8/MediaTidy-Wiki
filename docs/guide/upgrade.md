# 升级指南

## Docker 升级

### 标准升级流程

```bash
# 拉取最新镜像
docker pull murongyun574/mediatidy:latest

# 停止并删除旧容器
docker compose down

# 重新启动
docker compose up -d
```

### 指定版本升级

如需升级到特定版本，修改 `docker-compose.yml` 中的镜像标签：

```yaml
services:
  mediatidy:
    image: murongyun574/mediatidy:v0.0.21  # 指定版本号
```

然后重新启动：

```bash
docker compose up -d
```

## 0.1.4 功能与升级注意事项

0.1.4 会自动完成数据库迁移，无需手动执行 SQL。升级后重点检查以下项目：

- **CD2 读取强度**：旧的 CD2 全局请求限制和分类延时会保留在数据库中，但不再参与实际限流。请改为在 CD2 中设置各来源的最大下载线程数、可用时的每秒最大请求数，再在「网盘设置 → CD2 读取强度」选择低档 50%、均衡 75% 或满速 100%。
- **CD2 Token 权限**：令牌可访问目录建议设为 CD2 根目录 `/`。仅查看 / STRM 至少需要列出、读取和下载权限；整理、移动、复制或删除还需要相应写入与删除权限。
- **连集**：新增 `S01E01-E02` 等同季连续范围识别，并会严格逐集校验。跨季、倒序、非连续或歧义范围会留在原处或未识别目录，请不要用固定目标集或集偏移强行覆盖。
- **全局媒体封板**：新增「自动整理 → 封板管理」，可封板整部电影、整剧或指定季；封板只影响自动流程，已入库文件不会被移出。手动整理命中时必须明确确认绕过。
- **电影来源地区分类**：`origin_country` 现在匹配 TMDB 详情顶层来源国家/地区，`production_countries` 继续表示制作国家/地区。旧电影缓存按需补齐缺失字段，不会升级时全量刷新或覆盖锁定元数据。
- **115 高速穿透**：STRM 并发为“自动”时固定使用 4 路；需要更高吞吐可手动选择 8、16 或 32 路。
- **每日资源日报**：日报默认关闭，按北京时间发送；升级后需在通知设置启用，并在目标渠道勾选 `daily.summary`。服务离线错过定时点不会自动补发，可使用「立即发送昨天日报」。

授权验证、心跳和能力申请遇到网络抖动、429 或 5xx 时会在最多两个授权端点之间自动重试；协议、签名或证据校验失败仍会立即拒绝。已有有效授权不会因短暂网络故障提前失效。授权服务 V3 的默认配额调整为每 5 分钟验证 32 次、心跳 32 次、能力申请 256 次；管理员已自定义的运行策略不会被覆盖。

## 数据迁移

### 数据库自动迁移

MediaTidy 内置数据库迁移机制，每次启动时会自动检测并执行必要的数据库结构变更。**无需手动操作**。

### 备份建议

升级前建议备份 `data` 目录：

```bash
# 停止服务
docker compose down

# 备份数据
cp -r ./data ./data-backup-$(date +%Y%m%d)

# 升级并启动
docker pull murongyun574/mediatidy:latest
docker compose up -d
```

## 版本查看

当前运行版本可在以下位置查看：

- **管理面板**：左下角或「关于」页面
- **启动日志**：`MediaTidy starting version=x.x.x`
- **API**：`GET /api/version`

## 注意事项

::: warning 重要
- 升级前务必备份 `data` 目录（包含数据库和配置）
- 不建议跨多个大版本直接升级，建议逐步升级
- 如遇问题，可将备份的 `data` 目录还原后回退到旧版本镜像
:::
