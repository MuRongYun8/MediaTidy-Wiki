# 插件中心使用指南

插件中心首次打开时，已安装列表和发现目录都为空。MT 不附带 AI 识别插件，不推荐或预填任何插件仓库，也不会自动安装示例。SDK 的目录清单示例仅供开发者复制，不在宿主中内置。

## 安装与启用

1. 打开「插件中心」，点击「从仓库安装」。填写插件作者提供的 GitHub/Gitee 公开仓库地址；分支或标签留空时读取默认分支。
2. 点击「读取插件信息」。MT 解析固定提交，展示插件名称、版本、说明和权限。不能直接把 MT 主仓库或开发 Skill ZIP 当作可安装插件。
3. 勾选需要授予的能力和资源。目录的读取、写入和删除独立授权；整理、自动整理、STRM、通知、HTTP 目标也分别选择。
4. 确认安装后，打开插件设置，检查配置和资源，再由用户启用。安装或更新不会自行扩大授权。
5. 在插件页面选择动作、参数和文件。任务中心显示插件流程与业务子任务；入队、等待、执行成功是不同状态。

插件指定作品与季集的手动整理会生成宿主草稿，必须在 MT 中核验、修正并确认后才能入队。自动整理只有单独授权对应方案后才可直接运行。

## 定时与事件

插件可以定义多条周期或一次性任务，统一显示在插件设置和 MT 定时任务管理中。新建默认停用，用户检查参数、时区和资源后启用；暂停定时只影响后续触发，不取消已交给业务队列的任务。

耗时业务可以等待完成事件后续接动作。停用插件会阻止新动作和回调；已经提交的整理或 STRM 任务仍由 MT 管理。详情见[调度与任务事件](automation.md)。

## 数据与更新

「数据与存储」查看插件业务键、容量、历史和卸载保留数据，可导出或恢复非密钥业务数据。恢复前检查覆盖范围；存在活动或结果未知的任务时不可清空。详情见[存储与生命周期](storage.md)。

检查更新从已安装来源读取目标版本，安装前重新审阅。来源未记录的历史安装需要填写作者的实际仓库，不能猜测来源。回退代码不会回退业务数据，回退后保持停用。

SDK v1 插件保留数据和历史，标记不兼容；MT 不自动运行、迁移授权或安装替代插件。卸载默认保留业务数据，只有用户明确选择才清除。

## 开发入口

插件中心顶部和开发资源卡片均可下载[开发 Skill 完整包](downloads.md)，内容与当前 MT 的 SDK 版本一致。官方 Wiki 同时提供下载入口。

Skill 用于辅助编写插件，并非可安装的 MT 插件。插件作者从[开发入门](getting-started.md)开始；页面、Logo 和业务脚本都放在自己的插件仓库中，MT 使用受限 SDK 和组件协议提供运行能力。
