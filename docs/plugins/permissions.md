# 权限与远程 FF 数据保护

每次调用同时检查清单能力、用户授予的能力、具体资源、安装实例及修订、许可证和额度。能力发现接口仅帮助选择功能，不能代替实际授权。UI 禁用按钮也不是授权检查。

| 操作 | 资源权限 |
|---|---|
| 浏览、扫描、文本读取 | 源目录读取 |
| 创建、写入 | 目标目录写入 |
| 复制 | 源读取、目标写入 |
| 重命名 | 源目录写入 |
| 跨目录移动 | 源读取/写入/删除，目标写入 |
| 删除 | 独立删除授权；递归必须明确指定 |
| 自动整理 | 每个方案及方案组成员的自动执行授权 |
| 手动指定作品整理 | 授权方案、文件引用、MT 核验及用户最终确认 |
| 通知、HTTP | 指定通道，或目标地址/路径/方法 |

文件操作使用 MT 发出的引用与相对路径。不得接收任意宿主绝对路径。授权根本身不能删除；默认不覆盖，覆盖文本还需要目标文件当前引用。执行前复核文件版本和真实路径，阻断穿越、链接与 junction 逃逸。云盘不支持的操作返回 `UNSUPPORTED`，不绕过路由。取消保留已完成部分。

授权目录内的 STRM、NFO、字幕、自行生成的探测文本按普通用户文件处理，STRM 原文不会隐藏播放地址。授权读取同时意味着插件可以把这些文件内容用于获准的外部服务；MT 不宣称能够阻止其传播已经授予的数据。

远程 FF 资产采用另一边界：没有原文、轨道、SHA1 任意查询、缓存枚举/导出、节点配置或全局日志接口。内部数据库、内部缓存及其落盘副本、密钥文件不能成为普通目录授权；硬链接也不能绕过受保护文件检查。

`quality.prepare/evaluate/evaluateBatch/compare/upgrade` 仅接受授权文件引用与方案。数据准备可使用宿主缓存或探测，但只返回总分、资格、完整状态、固定原因类别和比较结论。不得提供自定义权重、公式或字段查询来逐项反推 FF 内容。评分计量按插件实例累计，不能通过清空 storage 重置。

HTTP 只通过 `mt.http.request`。Goja 没有 `fetch`、Socket、Node 网络模块、环境变量、命令或任意 Go 对象。请求不继承宿主 Cookie、模型密钥、云盘凭据或代理认证。目标授权包含方法和路径边界，私网需要额外选择；DNS、重定向和最终连接都校验。MT 自身、远程 FF 服务和云元数据地址始终禁止。

页面只能用白名单组件、属性、绑定和事件。禁止 HTML、脚本、CSS、表达式和任意 URL。文件名、模型输出和插件结果按文本渲染，不能改变页面结构、动作或权限。整理确认始终由 MT 的后端草稿产生，插件没有提交确认令牌的能力。

独立工作进程是受限能力边界，不等同完整操作系统沙箱。异常资源使用会终止进程；宿主管理员仍需使用正式发行的只读部署、最小权限及授权加固。开发工具不能替代真实权限和安全回归。
